# 破天宗 · 修仙模拟

依据《破天宗修仙模拟器 游戏设计开发文档》实现的网页版修仙模拟经营游戏，界面与交互按 **V1.4 增量改造清单** 升级。
纯静态前端（无构建步骤）+ WorkBuddy 云服务（账号、存档、榜单、赛季、兑换码、日志）。

## V1.4 场景与待处理

四条规则变更，全部落在表现层与事务流转上，核心数值、剧情文本、账号存档、对战赛季、兑换码均未改动。

1. **主页即宗门场景**：山体十层剖面 + 山脚破天城，十三处建筑可点。不再有独立总览页。
   点击建筑先高亮（`is-sel`），**再点一次**才进入面板——误触不会跳转。
2. **取消自动弹窗**：剧情、心魔、外敌、寿元、岗位、突破、邀约、赛季全部进待处理与消息中心。
   只保留三类阻断式提示：不可逆操作的二次确认、存档写入冲突、登录与会话异常。
3. **日常由破天阁自治**：三档施政策略（宽纵 / 均衡 / 严苛）× 四条法度（晨课 / 夜禁 / 厚赏），
   对修炼、产出、突破、忠诚、心魔产生乘数增量；补缺、招揽、疗养按日自动执行，每次写入宗门史可追溯。
4. **大事进祖师殿**：一次陈列三件，四段式卡片（事由 / 影响 / 三处置各附后果 / 附注），单件批阅。

待办**不落冗余副本**：全部由存档状态经 `deriveMatters()` 纯函数推导，多端天然一致；
存档写入时镜像一份到 `pending_matter`，供接口与其他端读取。批阅统一带 `req_id` 幂等，重复点击不重复结算。

## 画质与降级

四档画质（极简 / 流畅 / 标准 / 精细）控制 dpr、云层、雾气、人物、烟气、光晕、鸟群与细节装饰，
另有「减少动态效果」开关停掉逐帧循环（只在状态变化时重绘）。
帧率连续两个 1.5 秒窗口低于 26 帧会自动降一档并提示，功能完全不受影响。

## 玩法概要

- **身份与修为分离**：杂役以九星标识身份，正式弟子以九步标识；境界共二十阶，与步数多对一映射。
- **跃迁有阻力**：前三步随时间自然晋级；第三步晋第四步为批次竞争考核（最多四成通过、每人三次机会）；第四步之后按递减通过率判定；第九步亲传弟子只能由祖师指定。
- **经营闭环**：招收 → 修炼 → 突破 → 生产 → 任务与派遣 → 反哺招收。
- **四幕主线 + 十六个关键事件**，选择写入宗门史且不可撤销；终局三种结局。
- **三机构九席位**：弟子阁、护法堂、长老会，竞选按八维加权排序。
- **大世界与对战**：三方势力外交、派遣探索、邀约制对战、赛季榜单。

## 账号体系

**站点不提供手机号、邮箱等自助注册入口。** 登录页只有「账号 + 口令」，玩家账号一律由管理员在管理台开立。

- 初始管理员的账号名为 `admin`，初始口令由部署方单独保管（不在仓库中出现）。
- 新开账号首次登录必须先改密，改密前无法进入游戏主界面。
- 口令以服务端加盐 + 1500 轮散列存储，数据库与接口都不回传明文；客户端只持有会话令牌。
- 连续口令错误达到阈值（默认 5 次）临时锁定 15 分钟，管理员可在后台解锁。
- 改口令使该账号全部会话立即失效；管理员可强制下线、停用（保留数据）。

## 管理台（十页）

仅 `role=admin` 可见。设计前提是**只管人、不管数**：可以建号、发码、看数据、控节奏、开关模块，但不能直接改玩家资源、弟子属性与榜单分数。

| 页面 | 能做什么 |
| --- | --- |
| 总览 | 在线账号、账号总数、活跃存档、今日兑换、赛季状态、模块关闭数、声望前五、最近操作、清理到期存档 |
| 账号 | 建号（含槽位上限 3–10）、批量导入、重置口令、停用/启用、解锁、槽位授权、强制下线、跳转玩家数据 |
| 存档 | 检索、详情、封存/解封、留存快照、回滚、导出 JSON、删除（封存七日可撤销） |
| 玩家数据 | 账号、宗门概况、弟子结构（均境/心魔/寿元/步数分布）、资源存量、剧情进度、机构在任、对战战绩（只读） |
| 兑换码 | 单个发码、批量生成（≤50/次）、绑定账号专属码、停用/启用、核销记录、导出码表 |
| 赛季 | 开启、结束并锁定快照、重置、导出榜单、按名次批量生成专属奖励码 |
| 开关 | 七个模块独立启停 + 账号白名单灰度 |
| 日志 | 七类日志检索与导出（只追加，不可删除） |
| 设置 | 公告（玩家端顶部）、同时在线设备数、失败锁定阈值、令牌有效期 |
| 须知 | 后台能力边界与危险操作分级 |

危险操作（赛季重置、存档删除、存档回滚）均需二次确认并填写理由，写入日志；删除保留七日、回滚自动备份当前状态。

## 子系统开关与灰度

全服级，按模块粒度：宗门对战、排行榜与赛季、资源与生产、剧情、大世界、任务派遣、机构席位。

关闭后入口隐藏、接口拒绝、对应结算暂停，**已有数据原样保留**，重新开启即恢复。
模块关闭时可配置账号白名单，仅名单内玩家可见；白名单清空即回到全关状态。

此外 V1.4 另有两个**模块级灰度开关**，各自保留完整旧路径，出问题可一键回退：

| 开关 | 开 | 关 |
| --- | --- | --- |
| 场景开关 `sceneHome` | 主页走宗门场景 | 回退到旧的卡片看板（`#boardFallback`），canvas 不加载 |
| 提示模式开关 `pendingMode` | 事件进待处理与消息中心 | 回退到旧的阻断弹窗（含选项与后果） |

两者在 `js/config.js` 的 `FLAGS` 中声明，支持 `whitelist`（账号命中即强制开启）与 `percent`（按账号哈希的百分比灰度）；
管理员在「设置 → 灰度与回退」里可写本机覆盖值（`potian.flags`），切换后主页立即重建，刷新后仍生效。

## 本地运行

```bash
python -m http.server 8080
# 打开 http://localhost:8080
```

账号走自建接口，不依赖 OAuth 回调，因此在 localhost 也能正常登录与存取档。

## 云端结构

| 表 | 用途 |
| --- | --- |
| `accounts` | 账号、角色、状态、加盐散列口令、槽位上限、失败计数与锁定 |
| `sessions` | 会话令牌、设备类别、最后活跃 |
| `saves` | 每账号独立存档，含修订号、封存标记与待删除时间 |
| `save_snapshots` | 存档历史快照（后台回滚用） |
| `rankings` | 按赛季归档的榜单公开字段 |
| `seasons` | 赛季起止、状态与结束时的榜单快照 |
| `redeem_codes` / `redeem_logs` | 兑换码（含绑定账号）与核销记录 |
| `settings` | 公告、模块开关、白名单、安全策略（单行） |
| `admin_logs` | 七类操作日志，只追加 |
| `pending_matter` | 待办镜像：`save_id + ref` 唯一，`req_id` 幂等，`status` 记 open/done |
| `policy_setting` | 施政策略：档位、四区自决范围、招收门槛、四条法度（每存档一行） |

所有读写都经 `SECURITY DEFINER` 函数（`account_login` / `save_put` / `rank_push` / `redeem_code` /
`scene_state` / `pending_list` / `matter_act` / `policy_set` / `admin_*`），
表本身对匿名与登录角色一律 `REVOKE`；函数对 `PUBLIC` 收回执行权，仅内部工具函数保留私有。
客户端拿不到任何表结构，也读不到码表与他人存档。
存档写入带修订号校验：多端并发时旧版本会被拒绝并提示「数据已在其他设备更新，已为你刷新」。
槽位上限与封存状态由服务端校验，前端隐藏按钮不构成任何安全措施。

V1.4 新增的四个接口：

| 接口 | 用途 |
| --- | --- |
| `scene_state(token, slot)` | 场景状态查询（层数、已解锁建筑、待办聚合、策略摘要） |
| `pending_list(token, slot)` | 待处理列表（三级、按建筑归并） |
| `matter_act(token, slot, req_id, ref, action, note)` | 事项处置，action ∈ approve/reject/defer/ask，`req_id` 命中即返回 `dup:true` |
| `policy_set(token, slot, patch)` | 施政策略写入，跨端一致 |

## 上线验收对照

| 验收项 | 落点 |
| --- | --- |
| 主页无表格，首屏数字 ≤ 6 | 顶栏三个数字 + 场景两处浮标，合计 5；全站只此一处计数 |
| 场景可交互，误触不跳转 | 首次点击只高亮，第二次才 `onOpen`；热区为可聚焦按钮 |
| 十分钟内无遮挡式弹窗 | 仅三类阻断提示可弹；剧情/异动/心魔等只进待处理 |
| 待办有建筑发光与入口角标 | 热区 `.lv1/.lv2/.lv3` 分级发光 + `#btnPending` 红点 |
| 红点可清零 | 待处理「全部已读」写 `matterState.seenDay`，消息中心进入即已读 |
| 抽屉不遮场景中心 | 桌面右侧滑出、移动端底部抽屉（68vh），场景中心始终可见 |
| 祖师殿只含大事 | `memorials()` 只收剧情、异动、心魔≥55、寿元余<12 年、粮<200、席缺、交恶 |
| 自治可追溯 | 每次自决写 `chronicle('auto', …)`，含策略档位与结果 |
| 性能达标 | 单建筑 ≤ 800 面（Canvas 2D 绘制，非网格），整场一次预渲染 + 逐帧只画云/雾/人物/光晕；帧率低于阈值自动降档 |
| 多端一致 | 策略与待办以存档为准，`save_put` 镜像 `pending_matter`，`policy_set` 跨端下发 |

自测脚本覆盖引擎、界面交互与灰度回退三组，全部通过（见提交说明）。

## 已知边界

- 对战对手取自榜单公开字段，战斗由本地引擎按双方战力结算并写回战报；邀约需对方「应战」由规则模拟。
- 赛季「日常运行」阶段由玩家存档同步刷新榜单，不是服务端每小时定时任务。
- 离线收益上限 2400 游戏日。
- 令牌默认 168 小时（文档建议 2–24 小时），可在后台按 2–720 小时调整；放置类游戏长会话更实用。
